# TTS 诊断医生

排查「合成失败：返回的音频为空（44 字节）」。

## 核心思路

**44 字节说明服务端回了东西，只是不是音频。**

所以问题不是连不上，而是某个请求被拒了。可能是：
文本太长、含特殊字符、并发太多、发音人临时不可用。

这个插件把「服务端到底回了什么」原样打出来。

## 三条命令

| 命令 | 用途 |
|---|---|
| 诊断：跑一遍合成测试 | 全套：内容类型 + 长度梯度 + 并发 |
| 诊断：用当前笔记的真实分段测试 | 拿你现在这篇，逐段合成 |
| 诊断：复制上次结果 | 粘给别人看 |

## 测什么

**1. 连通性** — /voices 通不通

**2. 内容类型** — 10 种可疑内容：
换行、表格竖线、数字英文、百分号&符号、引号括号、emoji、长文本

**3. 长度梯度** — 50 到 3000 字，找临界点。
找到会直接告诉你「把每段字数调到 N 以下」

**4. 并发** — 1 / 3 / 5 个同时请求。
朗读插件会并行预取 3 段，看服务端扛不扛得住

## 跑完把结果发我

特别是「服务端返回」那几行 —— 那是定位的关键。

## 顺带修的（在朗读插件里）

原来只报「44 字节」，看不出所以然。现在会：

- 如果返回的是 JSON → 直接把 JSON 内容说出来
- 如果带 error 字段 → 只显示人话（比如「发音人忙」）
- 如果真是空音频 → 显示字节数 + HTTP 状态 + Content-Type

另外原来只认「带 error 字段的 JSON」，
遇到 `{"success":false,"code":500}` 这种会漏过去。
现在只要 Content-Type 是 JSON 就当错误处理。

# v1.1.0：认得「44 字节空 WAV」了

## 你截图里那个 44 字节是什么

`RIFF/WAVEfmt` —— 这是标准 WAV 文件头，**正好 44 字节**。

也就是说：请求发出去了，服务端也回了 200，
但**合成出来的音频是空的**——头有了，一个采样点都没有。

## 为什么会合成出空音频

发出去的文本是空的，或者整段没有可发音的字符。

典型场景：

1. **队列被换掉了** — AI 朗读结束后 `stop()` 清空 `chunks`，
   某个请求还拿着旧 index 去取 `chunks[i]`，取到 `undefined`
2. **设定集里的表格分隔行** — `| --- | --- |` 清洗后整段没内容

## 朗读插件已修（v2.5.0）

- `getAudio()` 先检查文本有没有可发音内容，没有就**不发请求**
- `playAt()` 遇到空段**自动跳到下一段**，不再卡住报错
- `splitChunks()` 切片时就过滤掉这类空段

## 诊断插件新增

内容类型测试里加了两个用例：`纯符号空段`、`只有标点`。
如果这两个报错，会在结论里明确提示「空音频（只有 WAV 头）」。
