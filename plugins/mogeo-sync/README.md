# 小说同步

把笔记备份到 GitHub 私有仓库。**只上传，不下载**，永远不会覆盖你本地的稿子。

## 备份到哪里

设置页顶部选目标，或者直接在面板点上面的三个按钮切换：

| 目标 | 适合谁 | 版本历史 | 一次同步 |
|---|---|---|---|
| **GitHub** | 要完整提交历史 | ✅ 有 commit | 一个 commit |
| **中国开源 / 自建** | 国内速度快，或公司自建 | ✅ 有 commit | 逐文件 |
| **坚果云** | 只要网盘备份，不想折腾 | 服务端保留 | 逐文件覆盖 |

三个是**单选**，同时只有一个生效。换目标不影响本地文件，只是下次同步传到新地方。

---

## ① GitHub

1. 建一个**私有**仓库
2. 生成有 `repo` 权限的 token：`https://github.com/settings/tokens/new`
3. 设置页填 Token / 用户名 / 仓库名 / 分支
4. 点「测试连接」

详细图解见仓库里的《GitHub注册与Token教程.md》。

## ② 中国开源 / 自建（自己填地址）

任何走 Contents API 的 Git 平台都能用。

**填「仓库 API 地址」，到仓库那一级：**

```
Gitee    https://gitee.com/api/v5/repos/用户名/仓库名
自建Gitea https://git.example.com/api/v1/repos/用户名/仓库名
```

另外填：访问令牌、分支（**Gitee 一般是 master**）。

用户名和仓库名只是用来在面板上显示，可填可不填。

> ⚠️ 这类平台的 Git Data API 大多只能读不能写，所以是**逐文件提交**，
> 一次同步会产生 N 个 commit（N = 改动文件数）。这是平台限制，不是插件问题。

## ③ 坚果云（WebDAV）

**要用「应用密码」，不是登录密码。**

拿应用密码：坚果云网页端 → 账户信息 → 安全选项 → 添加应用密码。

设置页填：账号（注册邮箱）+ 应用密码。

「云端文件夹」留空放根目录，填 `小说备份` 就存到那个文件夹里。

> WebDAV 没有 commit 概念，就是覆盖文件。坚果云服务端自己会保留历史版本，
> 但插件里看不到「上次提交了什么」——这是协议差异。
>
> 服务器地址默认坚果云，也能填其它 WebDAV（群晖、Nextcloud 等）。

## 首次设置（以 GitHub 为例）

1. 在 GitHub 建一个**私有**仓库
2. 生成一个有 `repo` 权限的 token：
   `https://github.com/settings/tokens/new`
3. 插件设置里填 Token / 用户名 / 仓库名 / 分支
4. 点「测试连接」确认通了

## 同步进度

点「立即备份」后，面板上会出现进度区：

```
正在备份…                    2/4
━━━━━━━━━━━━━━━━━━━━━━━━━━
↑  第003章 雨夜
✓  第001章 惊变
·  第002章 入局
·  第004章 破局
```

| 标记 | 意思 |
|---|---|
| `·` | 等待中 |
| `↑` | 正在传 |
| `✓` | 传完了 |
| `–` | 没变化，跳过 |

**超过 8 个只显示前 8 条**，下面一行写「还有 N 个」——手机上全列出来会很长。

传完显示「备份完成」，右上角有「清空」。失败会把原因直接写出来（比如「账号或应用密码不对」），不用去猜。

> 进度只是**看**的，关掉面板不会中断同步。

## 中途停止

备份过程中，进度区右上角会出现红色「**停止**」按钮。命令面板里也有「停止备份」。

```
正在备份…              2/5     [停止]
━━━━━━━━━━━━━━━━━━━━━━━━━━
✓  第001章 惊变
✓  第002章 入局
↑  第003章 雨夜
·  第004章 破局
·  第005章 终局
```

停止后：

```
已停止                  2/5     [清空]
━━━━━━━━━━━━━━━━━━━━━━━━━━
已传完的会记住，剩下的下次接着传
```

**下次同步只传剩下的**，不会从头再来。

> ⚠️ **已经在传的那个文件停不掉** —— Obsidian 的网络请求不支持中途取消。
> 点停止后，当前这个会传完，然后不再发下一个。
>
> **GitHub 模式更特殊**：它是一次性 build tree + commit，中间没有停点。
> 只有在这次提交**开始前**点停止才有效；已经进提交流程就只能等它走完。
> 国内 Git 平台和坚果云是逐文件传的，随时能停。

## 长按文件夹

长按左侧文件列表里的任意文件夹，菜单里有：

```
📤 同步此文件夹到坚果云
```

**后面的名字跟着当前目标变**——切到 GitHub 就显示「同步此文件夹到 GitHub」，不会误导。

## 三种触发方式

### 1. 左侧栏面板
自动挂载，显示仓库名、上次同步时间、文件夹列表。
点「立即备份」或某个文件夹右边的「同步」。

### 2. 长按文件夹
在文件列表里**长按任意文件夹** → 「📤 同步此文件夹到 GitHub」

只传这个文件夹，适合刚写完一章马上备份。

### 3. 命令
- 立即备份到 GitHub
- 打开同步面板
- 测试连接

## 同步范围

设置里「要备份的文件夹」一行一个，**留空 = 整个 vault**。

「忽略规则」也是一行一个，三种写法：

```
.obsidian        ← 目录名（任意层级都命中）
*.tmp            ← 通配
草稿             ← 前缀
```

默认已排除 `.obsidian`，所以不会把插件配置传上去。

## 增量 + 一次提交

**不是每次全传。** 用 git blob 指纹比对，只传真正变过的文件。

```
第一次：传 3 个 → 1 个 commit
第二次：无变化 → 什么都不做，不产生 commit
改一章：只传 1 个 → 1 个 commit
```

历史长这样：

```
备份 2026-09-08 14:32 · 3 个文件
备份 2026-09-08 15:10 · 1 个文件
```

不会像「每文件一提交」那样刷屏。

## 远端目录前缀

默认放仓库根目录。填 `books` 就会变成 `books/小说相关/第一章.md`。

## 关于「只上传」

插件**不会**从远端下载任何东西。所以：

- ✅ 当云端备份用，防止手机丢了稿子没了
- ✅ 多设备时，在另一台点一次同步就能推上去
- ❌ 不会自动把远端的改动拉回本地

如果你在两台设备上交替写，拉回的那一端需要手动去 GitHub 下载，或者用 Git 客户端。

> 做成单向是刻意的：双向合并会涉及冲突处理，在手机上体验很糟，
> 而且备份场景下「本地永远是最新」这个假设更安全。

## 文件放哪了

```
remoteRoot（留空则仓库根）
└── 小说相关/
    └── 第一章.md
```

路径结构和 vault 里完全一致，在 GitHub 网页上能直接浏览。

## 常见问题

**测试连不上**

- **Token 无效或已过期** → 重新生成
- **仓库不存在，或 Token 没权限** → 检查用户名/仓库名，确认 token 勾了 `repo`

**同步很慢**

第一次慢是正常的（要传所有文件）。之后只传变化的。
如果文件特别多，建议缩小同步范围。

**「清除同步记录」是什么**

存的是每个文件的指纹，用来判断变没变。
清掉不会丢文件，只是下次会全量比对一次。

**Token 会上传吗**

不会。Token 只存在本地 `data.json`，插件本身不向任何第三方发送数据
（只和你自己的 GitHub 仓库通信）。

但要注意：**别把整个 vault 公开上传**，因为 `data.json` 里有 Token。
