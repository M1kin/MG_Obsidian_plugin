# Mogeo 插件套件

一套给 **Obsidian 手机端** 做的小说创作工具链，共 9 个插件。

从建书、写作、改稿、朗读到导出，全流程覆盖。安卓 / iOS 可用，界面按手机竖屏设计。

> 📖 **[完整使用指南 →](使用指南.md)**

---

## 插件一览

|---|---|---|---|
| **Mogeo Core** | 2.0.2 | 依赖中枢 + 状态中心 + 打赏聚合 | ✅ 必须 |

## 安装

### 第一步：装 Core（必须）

Core 是整个套件的地基，其他插件都要它在场。

```
设置 → 第三方插件 → 关闭「安全模式」
     → 把插件文件夹放进 .obsidian/plugins/
     → 重启 Obsidian
     → 打开 Mogeo Core 的开关
```

### 第二步：装你需要的插件

| 我想…… | 装这个 |
|---|---|
| 把 md 合成一个 txt | Folder to TXT |
| 听 AI 念我的笔记 | MultiTTS Reader |
| 批量改人名 / 地名 | 文件夹查找替换 |
| 让 AI 帮我写 | AI 写作助手 |
| 把 AI 的回复念出来 | AI 回复朗读 |
| 管理一整本书 | 书籍写作 |
| 一个面板点完所有操作 | 创作工作台 |

**装完重启 Obsidian。**

### 第三步：验证

Core 设置页点紫色「一键检查」，会显示每个插件是 🟢 可用 / 🟡 未启用 / ⚪ 未安装。

## 依赖链

```
Mogeo Core           ← 所有插件的地基
├── Folder to TXT
├── MultiTTS Reader
├── 文件夹查找替换
├── AI 写作助手
│   └── AI 回复朗读    ← 还要 MultiTTS Reader
├── TTS 诊断医生
├── 书籍写作
└── 创作工作台
```

**AI 回复朗读** 要求最严：Core + AI 写作助手 + MultiTTS Reader 三个都得在。

关掉 Core，其他插件会拒绝执行并跳到设置页 —— 这是**故意的**。

## 典型工作流

**写一本新书**

```
书籍写作 → 新建书籍 → 新建章节 → 写
  → AI 写作助手续写 / 润色
  → MultiTTS Reader 边写边听
  → 文件夹查找替换 统一人名
  → 导出 TXT
```

**日常码字**

在创作工作台建个「开写前」分组，放 新建章节 / 朗读 / 查找替换，一点就走。

## 开发者接入

新插件接入 Core 只要三行：

```js
const Mogeo = require('./mogeo');

async onload() {
  const M = Mogeo.boot(this, { id: 'my-plugin', name: '我的插件' });
  if (!M) return;
  // 之后随便写
}
```

Core 启用 → 正常跑；没启用 → 自动提示并跳设置页。

详见 [接入文档.md](接入文档.md)。

## 常见问题

**点了命令没反应？** → Core 没启用，打开开关后重启。

**悬浮朗读条不出现？** → 确认插件已启用、设置里「显示悬浮条」是开的，重启一次。

**朗读报「返回的音频为空」？** → 跑一遍 TTS 诊断医生。若是 44 字节，说明发出去的文本没内容可念。

**AI 连不上？** → 看错误码：401 Key 错 / 429 限流 / 404 模型名不对 / 余额不足去充值。

完整 FAQ 见 [使用指南.md](使用指南.md#常见问题)。

## 隐私提醒

- **API Key 明文存在 `data.json`** —— 别把整个 vault 公开上传
- **AI 请求会发送到你配置的服务商** —— 正文会离开设备，介意的话用本地模型
- **TTS 请求发往你填的地址** —— 默认本机 `127.0.0.1:8774`，不外传
- **所有插件都不上传任何数据到作者服务器**
